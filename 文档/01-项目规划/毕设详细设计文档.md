## 一、课题概述

### 1.1 课题来源与研究目标

本课题面向 **AI 生成内容（AIGC）的安全与可靠性测试** 需求，研究并设计一套融合 **RAG（检索增强生成）与提示工程（Prompt Engineering）** 的隐性广告智能识别测试方案。

### 1.2 核心研究问题

如何利用大语言模型的语义理解能力，结合外部知识库提供的权威法规与判例，自动化地识别一段文本内容中是否含有隐性广告，并给出合规性判定与风险分级？

### 1.3 课题产出的核心价值

- 形成一套 **可复现、可量化、可扩展** 的 AI 内容安全测试流程
- 构建面向隐性广告识别的垂直领域知识库
- 验证 RAG + 提示工程的协同增益效果（通过消融实验量化）

### 1.4 关键术语定义

| 术语 | 定义 |
|------|------|
| **隐性广告** | 未明确标注为广告，但以内容形式（种草笔记、测评、软文等）实质传递商业推广信息的内容 |
| **RAG** | Retrieval-Augmented Generation，检索增强生成——先检索外部知识，再喂给大模型，让回答有据可依 |
| **提示工程** | 通过精心设计输入指令（Prompt），引导大模型按特定逻辑完成推理判断 |
| **向量数据库** | 将文本转为数学向量后存储，支持"语义相似度搜索"而非关键词匹配 |
| **Embedding** | 文本向量化，将一段话映射为一组数字（向量），语义相近的文本向量距离也相近 |

## 三、核心技术栈详解

### 3.1 技术栈总览（v2.0 最终版）

| 层级 | 技术 | 用途 | 选型理由 |
|------|------|------|---------|
| **编程语言** | Python 3.13 | 全栈开发 | 生态最完善，AI/NLP 库最丰富 |
| **大模型 API** | **DeepSeek API**（`deepseek-chat`） | 核心推理引擎 | 国内直连、中文能力强、按分计费、微信充值 |
| **Embedding 模型** | **`BAAI/bge-m3`**（本地部署） | 文本向量化 | 中文 Embedding 效果 SOTA、支持多语言、1024 维向量、通过 ChromaDB 内置支持直接加载 |
| **向量数据库** | **ChromaDB** | 向量存储与检索 | 零配置、原生支持 sentence-transformers、Python 优先 |
| **RAG 实现方式** | **ChromaDB + DeepSeek 原生 API** | RAG 检索链路 | 代码量更少、去框架化、避免 LangChain 版本兼容风险 |
| **后端框架** | **FastAPI** | RESTful API 服务 | 高性能、自动生成 Swagger 文档、Pydantic 数据校验 |
| **前端** | **Streamlit** | 交互式 Web Demo | 纯 Python，无需 HTML/CSS/JS 基础 |
| **数据处理** | Pandas | 测试数据集管理、统计分析 | Python 数据分析必备 |
| **实验评估** | scikit-learn | 计算准确率/召回率/F1 | 标准 ML 评估库 |

### 3.2 各技术选型对比分析

#### RAG 实现方式选型（关键决策）

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|:---:|
| LangChain | 社区大、模块化 | **版本迭代快（一年发 3 个大版本）、网上教程大量过期、抽象层多调试困难** | ⭐⭐ |
| LlamaIndex | 数据索引专业 | 社区较小 | ⭐⭐⭐ |
| **原生实现（ChromaDB + 原生 API）** | **代码量最少（~15 行）、完全可控、无版本兼容风险、出问题容易排查** | 无现成模板 | ⭐⭐⭐⭐⭐ |

**最终选择：原生实现。** ChromaDB 的查询只需要一行 `collection.query()`，DeepSeek API 调用也只需要 `client.chat.completions.create()`，中间不需要任何框架层。论文中可以写"采用轻量化原生实现方案，避免了框架抽象带来的额外复杂度和版本兼容风险"。

#### 为什么去掉 LangChain？

```
LangChain 对零基础用户的实际体验：

  pip install langchain
  ↓ 
  拉下来 50+ 个依赖包
  ↓
  按照官方 Tutorial 写代码
  ↓
  报错：ImportError: cannot import name 'XXX' from 'langchain.xxx'
  ↓
  搜 StackOverflow → 发现是版本问题 → 降级 → 又和其他包冲突
  ↓
  一周过去了，还没开始写业务逻辑

原生实现：

  pip install chromadb openai
  ↓
  collection.query(query_texts=[text], n_results=3)  # 检索
  client.chat.completions.create(model="deepseek-chat", ...) # LLM
  ↓
  半小时跑通
```

#### 大模型 API 选型

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|:---:|
| **DeepSeek** | 国内直连、中文能力强、¥1/百万 tokens、微信充值 | API 稳定性待长期验证 | ⭐⭐⭐⭐⭐ |
| OpenAI GPT-4o | 行业标杆 | 需梯子 + 国际信用卡 + 贵 10 倍 | ⭐⭐⭐ |
| 通义千问 (阿里) | 国内直连、免费额度多 | 推理复杂逻辑略逊 | ⭐⭐⭐ |
| GLM (智谱) | 学术友好 | 生态较小 | ⭐⭐⭐ |

**最终选择：DeepSeek API。**

#### Embedding 模型选型

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|:---:|
| **`BAAI/bge-m3`（本地）** | 中文 SOTA、免费、无 API 延迟、ChromaDB 原生支持 | 需首次下载模型（~2GB）、需梯子 | ⭐⭐⭐⭐⭐ |
| `BAAI/bge-large-zh-v1.5`（本地） | 纯中文优化、体积稍小 | 不支持多语言 | ⭐⭐⭐⭐ |
| `shibing624/text2vec-base-chinese`（本地） | 轻量 | 效果不如 BGE 系列 | ⭐⭐⭐ |
| API Embedding（硅基流动/OpenAI） | 无需下载 | 依赖网络、有费用 | ⭐⭐⭐ |

**最终选择：`BAAI/bge-m3`（本地部署）。**

理由：
1. 你有梯子，可以从 HuggingFace 下载模型（一次性，下载完就离线可用）
2. ChromaDB 内置 `SentenceTransformerEmbeddingFunction`，两行代码加载
3. 论文可写"本地 Embedding 方案避免了云端 API 的网络延迟与数据隐私风险"
4. BGE-M3 是中文 Embedding 目前效果最好的开源模型之一

### 4.2 RAG 检索模块

#### 4.2.1 技术流程（原生实现，不使用 LangChain）

```
┌──────────────┐     ┌──────────────────────┐     ┌──────────────┐
│  用户输入文本  │ ──▶ │ BGE-M3 本地模型       │ ──▶ │  查询向量 Q   │
│  (Query)      │     │ (ChromaDB 内置加载)   │     │  [1024 维]   │
└──────────────┘     └──────────────────────┘     └──────┬───────┘
                                                          │
                     ┌─────────────────┐                  │ 余弦相似度
                     │  Top-K 结果      │ ◀───────────────┘ 检索
                     │  (排序后)        │
                     └────────┬────────┘
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
   │ 最相关法规   │    │ 最相似案例   │    │ 最匹配话术   │
   │ (k1=3)      │    │ (k2=3)      │    │ (k3=3)      │
   └─────────────┘    └─────────────┘    └─────────────┘
```

#### 4.2.2 核心代码结构（伪代码 → 实际代码量约 50 行）

```python
import chromadb
from chromadb.utils import embedding_functions
from openai import OpenAI

# ===== 初始化（应用启动时执行一次） =====
# 1. 加载本地 BGE-M3 Embedding 模型
embed_fn = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="BAAI/bge-m3"
)

# 2. 连接 ChromaDB
chroma_client = chromadb.PersistentClient(path="./knowledge_base/chroma_db")

# 3. 获取四个子库的 Collection（每个独立索引）
laws_col = chroma_client.get_collection("ad_laws", embedding_function=embed_fn)
cases_col = chroma_client.get_collection("ad_cases", embedding_function=embed_fn)
templates_col = chroma_client.get_collection("ad_templates", embedding_function=embed_fn)
brands_col = chroma_client.get_collection("ad_brands", embedding_function=embed_fn)

# 4. 初始化 DeepSeek 客户端
llm = OpenAI(api_key="your-key", base_url="https://api.deepseek.com")

# ===== 检索函数 =====
def retrieve_knowledge(query_text: str, k: int = 3) -> dict:
    """多路召回：从四个子库分别检索 Top-K"""
    return {
        "laws": laws_col.query(query_texts=[query_text], n_results=k),
        "cases": cases_col.query(query_texts=[query_text], n_results=k),
        "templates": templates_col.query(query_texts=[query_text], n_results=k),
        "brands": brands_col.query(query_texts=[query_text], n_results=k),
    }

# ===== 判定函数 =====
def detect_advertisement(text: str) -> dict:
    """完整的 RAG 推理流程"""
    # Step 1: 检索
    knowledge = retrieve_knowledge(text, k=3)

    # Step 2: 拼装 Prompt
    prompt = build_prompt(text, knowledge)

    # Step 3: LLM 推理
    response = llm.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1  # 低温度保证输出稳定
    )

    # Step 4: 解析结果（多层容错）
    return safe_parse_json(response.choices[0].message.content)
```

#### 4.2.3 检索增强策略

| 策略 | 说明 |
|------|------|
| **多路召回** | 分别从法规库、案例库、话术库、品牌库四个维度检索，再合并 |
| **Top-K 参数** | 每路子库返回 K=3 条，四条路共 12 条（在 DeepSeek 128K 上下文窗口内完全够用） |
| **相似度阈值** | 余弦相似度 < 0.5 的结果予以过滤，避免噪声干扰 |
| **本地 Embedding** | BGE-M3 首次从 HuggingFace 下载后缓存在本地，后续离线可用、无延迟、零费用 |
| **重排序（Rerank）** | 可选进阶功能：使用 BGE-Reranker 对初检结果精排（论文展望中讨论） |

#### 4.3.2 多策略提示工程对比方案（实验设计用）

| `violation_type` | array | 未标注广告 / 虚假宣传 / 误导性陈述 / 未披露利益关系 / ... | 违规类型标签 |

#### 4.4.2 风险分级标准

| 风险等级 | 判定标准 | 示例 |
|---------|---------|------|
| **高风险** | 明确违反广告法核心条款（如虚假宣传、绝对化用语）+ 有欺诈意图 | "用了一周年轻10岁"（虚假夸大） |
| **中风险** | 未标注广告 + 有商业推广意图，但内容基本属实 | 种草笔记未标"广告"但产品描述属实 |
| **低风险** | 内容含品牌提及但无明确推广意图，或广告标识不够显著 | 评测文章中自然提到多个品牌 |
| **无风险** | 纯内容分享，不涉及商业推广 | 普通日常分享 |

#### 4.4.3 实验评估指标体系

| 指标 | 公式 | 含义 |
|------|------|------|
| **准确率 (Accuracy)** | (TP+TN) / Total | 整体判断正确的比例 |
| **精确率 (Precision)** | TP / (TP+FP) | 判为"广告"中真正是广告的比例 |
| **召回率 (Recall)** | TP / (TP+FN) | 所有真实广告中被检出的比例 |
| **F1 分数** | 2×P×R / (P+R) | 精确率与召回率的调和平均 |
| **风险分级准确率** | Correct_Level / Total | 风险等级判定正确的比例 |
| **平均判定时间** | 毫秒 | 单条文本的平均响应时间 |

3. **本科毕设量级合理**：聚焦一个核心问题做深，优于铺多个方向做浅

### 本地模型文件说明

```
首次运行 ChromaDB + BGE-M3 时：
1. ChromaDB 检测到使用了 SentenceTransformerEmbeddingFunction
2. 自动从 HuggingFace 下载 BAAI/bge-m3 模型（约 2GB）
3. 缓存到 ~/.cache/huggingface/hub/
4. 后续启动直接从缓存加载，无需网络，加载时间约 5-10 秒

注意：
- 首次下载必须有梯子
- 下载完成后模型在本地，后续无网络也能用
- 如果下载中断，删除缓存目录后重试即可
```
