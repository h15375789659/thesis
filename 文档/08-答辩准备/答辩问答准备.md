## Q1：你这不就是调用了一个 API 吗？有什么技术含量？

**（导师可能的质疑：工作量/创新点不足）**

### 回答要点

1. **承认事实**：是的，代码层面 LLM 调用确实就是 `client.chat.completions.create()` 一行。

2. **但技术含量不在"发请求"，而在请求的前后两端**：

| 环节 | 谁在做 | 内容 |
|------|--------|------|
| 上游：喂什么 | 我 | 检索出最相关的法规 + 案例（知识库 + 向量检索） |
| 中游：怎么问 | 我 | 设计角色、四维判定规则、思维链、输出格式 |
| 下游：怎么用 | 我 | 5 层容错解析不稳定的 JSON 输出 |
| 中间那一下 | 现成 API | 发请求 |

3. **这是业界主流**：大量企业 AI 应用就是调 API（OpenAI/DeepSeek/通义），不是自己训练模型。自己训练需要海量标注数据 + 百万级 GPU 投入，不是本科量级。

4. **我的创新点不在"训练模型"**，而在"检索增强 + 提示工程如何协同提升通用模型在广告合规垂直领域的表现"，并用消融实验量化证明。

5. **论文严谨性体现在实验设计**（4 组对照、150 条标注测试集、多指标评估），而不是"是否自己写了 API"。

## Q2：我直接把疑似广告的话发给 AI 问，跟你这套系统的效果是不是差不多？

**（导师可能的质疑：RAG 是否真的有必要）**

### 回答要点

1. **诚实承认**：对**简单、明显**的广告文本，直接问和用系统问，效果确实差不多（LLM 本身有广告法常识）。

2. **差别体现在"难、边缘、需要精确依据"的场景**：

| 场景 | 裸 LLM（直接问） | RAG + PE（系统） |
|------|-----------------|-----------------|
| 需要引用具体条文 | 可能记混条号、编造条文（幻觉） | 引用检索到的**真实原文** |
| 新法规（2023 互联网广告管理办法） | 训练数据截止，不知道 | 知识库里有时效的新条文 |
| 判例参照 | 无判例可参照 | 检索真实处罚案例辅助判断 |
| 100 条文本判定一致性 | 标准漂移，时严时松 | 固定角色+规则，标准稳定 |

3. **"差多少"正是要用消融实验量化证明的**——这就是论文的贡献本身。

4. 反问逻辑：如果实验证明 D 组（完整）明显优于 A 组（裸 LLM），说明 RAG 有价值；如果差不多，那也是一个真实的、可分析的研究发现（什么场景才需要 RAG）。两种情况论文都能写。

## Q3：让 AI 直接检索广告法不就行了？为什么要大费周章建知识库？

**（导师可能的质疑：知识库的必要性 / RAG 与 LLM 内部知识的关系）**

### 回答要点

1. **纠正核心误解**：LLM 是"生成"模型，不是"检索"模型。它没有数据库可查，让它"检索广告法"只是**凭训练记忆去背**，这是"回忆"不是"查证"。

2. **凭记忆背法条会出三种问题**：
   - **记不精确**：记得"广告要有可识别性"，但具体是第十四条还是第二十八条？原文措辞？
   - **会编造（幻觉）**：不确定时生成一个"看起来合理但错误"的条文
   - **会过时**：2021 广告法修订、2023 互联网广告管理办法，训练截止后不知道

3. **RAG 的本质 = 把"闭卷考试"变成"开卷考试"**：

| | 闭卷（裸 LLM） | 开卷（RAG） |
|---|---|---|
| 答案依据 | 脑子里的记忆（不可靠） | 递到面前的真实法条（可查证） |
| 引用条文 | 可能张冠李戴 | 一字不差的原文 |

知识库 = 提前准备的"权威开卷资料"，不是多此一举。

4. **为什么不让它联网搜**：
   - DeepSeek 普通 API 没有联网能力（纯文本生成接口）
   - 网上搜索结果是泛化网页（有解读、广告、错误版本），自己建库是清洗过的权威原文 + 真实判例，质量天差地别。

## Q4：你的知识库为什么从四个子库收敛到三个？品牌库为什么砍掉？

**（导师可能的质疑：设计文档和实际实现不一致 / 知识库结构的决策依据）**

### 回答要点

1. **设计收敛：四个库 → 三个库**。最初设计文档规划了四个子库（法规/案例/品牌/话术），实现时收敛为三个，砍掉了品牌库。

2. **砍品牌库的原因**：LLM 训练数据本身已包含大量品牌知识，它"天然知道"什么是品牌、常见品牌名。单独建品牌库、检索出来再喂给它，属于**冗余**。这体现了对 LLM 能力的理解——不是所有知识都需要外部增强。

3. **话术库定位为"可选增强"**：不默认启用，而是通过 mode 参数控制，用于「两库 vs 三库」对比实验——验证话术库是否真的带来增益。

4. **技术实现：一个模板 + 一个插槽 + mode 参数**（两库/三库切换）：
   - FULL_PROMPT 里埋一个 `{template_section}` 占位符（插槽）
   - `mode="full"`（两库）→ 插槽填空，Prompt 无话术段
   - `mode="full_templates"`（三库）→ 插槽填话术内容，Prompt 多出"匹配话术模板"段
   - 同时 `rag_pipeline` 根据 mode 决定是否检索话术库

5. **这个设计的价值**：让"两库 vs 三库"的对比只差"有没有话术"这一个变量，正符合消融实验"每次只变一个变量"的原则——无论话术库有没有用，都能得出可写进论文的结论。

## Q5：测试集的标准答案由谁标注？AI 标注不是更准吗？

**（导师可能的质疑：数据标注的科学性 / 循环论证风险）**

### 回答要点

1. **诚实承认**：规则明确的情况下，AI 按规则标注确实比普通用户更准、更一致（不会疲劳、不漏细节）。

2. **但精度高 ≠ 可作金标准**：用 AI 标注的数据评估 AI 系统，是**循环论证**——两个 LLM 对"软广"的识别能力高度相似，会导致准确率虚高，测不出系统相对于"真实人类判断"的价值。

3. **规则的源头是人**：标注规则是根据《广告法》等法规和执法实践总结的，权威性最终追溯到人的判断。

4. **灰色地带需要人的价值判断**：规则能覆盖"有无品牌/链接"这类客观题，但覆盖不了"分享算不算变相推广"这类主观题。

5. **务实方案：AI 辅助标注 + 人工复核**：
   - AI 给出初步判断 + 理由 + 命中的规则
   - 人对照规则确认或修正，最终拍板
   - 论文如实写"AI 辅助标注 + 人工复核，确保反映人类判定标准"

## Q6：判断"是不是广告"纯 LLM 就够用，凭什么说 RAG 有用？

**（导师可能的质疑：RAG 增益不明显 / 消融实验结果可能翻车）**

### 回答要点

1. **承认合理之处**：对于"是否广告"这个基础判断，纯 LLM 凭常识（品牌 + 推销话术）确实够用，RAG 增益可能有限。

2. **但系统价值不止"是否广告"**，还包括：
   - 风险等级（高/中/低）—— 需要法规标准
   - 违规类型 —— 需要法规知识
   - 法律依据 —— 需要精确法条

3. **RAG 的价值在后三项**：LLM 判断"违反哪条法规"会记错/编造（幻觉），RAG 检索真实法条原文，保证法律依据可追溯、不编造。

4. **评估维度要扩展**（不能只看 is_ad 的 F1）：
   - is_ad 准确率（RAG 增益可能小）
   - 风险分级准确率（RAG 增益明显）
   - 法律依据正确率（RAG 增益明显）
   - 违规类型准确率（RAG 增益明显）

5. **论文的诚实结论**：RAG 对基础判定增益有限（LLM 本身具备软广识别常识），但在风险分级、法律依据引用、违规类型识别上显著提升，有效抑制幻觉。这反而精确回答了"RAG 到底增强在哪"。

## Q7：品牌露出就是隐性广告吗？（翻包 EDC 的标注分歧）

**（可能的追问：系统对品牌露出的误判 / 广告的认定标准）**

### 回答要点

1. **列品牌 ≠ 推荐品牌**：翻包 EDC 列了 12 个品牌但无推销话术（无"好用/回购/闭眼入"），不算广告。

2. **广告的法律本质是"商业利益关系"**，不是"主观推荐意图"，也不是"影响力"：
   - FMVP 夺冠用的刀涨价 → 名人效应，无商业利益 → 非广告
   - 品牌付费让 KOL 翻包 → 有商业利益 → 隐性广告

3. **系统的缺陷**：对"品牌露出密度"过度敏感，把"罗列品牌"误判为"推销品牌"（test_001 全军覆没）。

4. **标注标准**：看"推销话术"，不看"品牌数量"——有推销话术（安利/回购/闭眼入）才是广告特征。

5. **论文价值**：这个误判可作为"典型判定案例分析"素材，说明仅凭品牌提及不足以判定广告。

## Q8：系统输出的置信度（confidence）可信吗？

**（可能的追问：confidence 的含义 / 是否精确）**

### 回答要点

1. **诚实回答：confidence 是"编的"不是"算的"**。LLM 输出置信度是"接话"接出来的，本质是模仿"置信度怎么写"的语言习惯。

2. **实证证据**：实测 confidence 只有 0.85/0.90/0.95 三个离散值——精确计算的概率不会是三个整数字。

3. **但相对区分度成立**：LLM 虽"编"，但"确定就编高（0.95）、拿不准就编低（0.85）"，能粗粒度区分确定/不确定。

4. **论文正确写法**：confidence 是"模型自评的离散把握度（约三档）"，不是"经过校准的概率"。

5. **实用价值**：可用于阈值筛选（低置信度转人工复核），拦截"系统自己也拿不准"的判定。

## 附：基础概念（答辩前确保能讲清楚）

### 消融实验（Ablation Study）

- **字面**：来自医学"消融"= 切除。AI 里 = "拆掉系统一个零件，看效果降多少"。
- **类比**：熬汤分别不放盐/姜/八角，对比味道，证明每种调料是否必要。
- **本项目**：完整方案 D（RAG+PE），分别拆掉 RAG（组 C）、拆掉 PE（组 B）、全拆（组 A），用 F1 分数差证明每个部分各自的贡献。

### Embedding 与向量检索

- Embedding = 把文字变成一串数字（BGE-M3 输出 1024 维），语义相近 → 向量距离近。
- 向量数据库 vs 传统数据库：关键词精确匹配 → 语义模糊匹配。
- 例证（本项目实测）：查"新闻里能不能偷偷插广告"命中"不得以新闻报道形式变相发布广告"，两句话零词重合。
